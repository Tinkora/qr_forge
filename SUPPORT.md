## Choose the Right Channel

| Need | Channel |
| ------ | --------- |
| Setup, usage, or design question | [GitHub Discussions](https://github.com/Tinkora/qr_forge/discussions) |
| Reproducible bug | [GitHub Issues](https://github.com/Tinkora/qr_forge/issues/new/choose) |
| Feature proposal | [GitHub Discussions](https://github.com/Tinkora/qr_forge/discussions) before an issue |
| Suspected vulnerability | [Private vulnerability report](https://github.com/Tinkora/qr_forge/security/advisories/new) |

Never include passwords, private URLs, contact records, access tokens, or other sensitive QR payloads in a public issue or discussion. Replace them with minimal synthetic values that reproduce the problem.

## Before Asking

1. Read the [README](./README.md), [Product Contract](./docs/CONTRACT.md), and [Maturity](./docs/MATURITY.md).
2. Check existing issues and discussions.
3. Reproduce with the latest GitHub release or the current Pages deployment.
4. Record the browser, operating system, version or commit, input mode, and output format.

For scanner compatibility, identify the scanner and include a non-sensitive sample output when possible. For build failures, include the failing command and relevant error output, but remove tokens and local secrets.

## Support Boundaries

Community support is best effort and has no guaranteed response time. Maintainers support the latest GitHub release and current project deployment, not custom forks, unrelated barcode hardware, browser extensions, or third-party hosting configurations.

General questions belong in Discussions. Issues should describe behavior that can be acted on. Security reports must follow [SECURITY.md](./SECURITY.md).
