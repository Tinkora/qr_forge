# 成熟度与兼容性

[English](./MATURITY.md)

## 当前状态

qr_forge 0.1 是早期公开版本。核心生成路径已经实现并经过测试，但项目还不是稳定的 1.0 API，也不是通过通用认证的条形码生产系统。

| 范围 | 状态 | 证据与限制 |
| ------ | ------ | ------------ |
| 二维码生成 | 可用 | 单元测试覆盖生成和限制；PNG 输出由独立扫描器库解码 |
| Code 128 | 在契约范围内可用 | 测试覆盖可打印 ASCII 和尺寸限制；生成的 PNG 已独立解码 |
| EAN-13 | 在契约范围内可用 | 测试覆盖校验位、精确输入、标准静区和独立解码 |
| SVG 和 PNG 渲染 | 可用 | Native 测试验证两种格式；实际输出仍需检查对比度和扫描器 |
| PNG Logo 叠加 | 实验性 | 测试覆盖输入和比例限制；可扫描性取决于 payload、Logo、尺寸、对比度和扫描器 |
| 浏览器应用 | Beta | 已在 Chromium 中验证 375、768、1024 和 1440 像素宽度；更广泛的浏览器自动化还不能构成兼容保证 |
| Rust API | 1.0 之前 | 公开并经过测试，但类型和 signature 在 1.0 前可能变化 |
| WASM API | 1.0 之前 | 由内置应用使用；没有单独版本化的 npm distribution |
| 无障碍 | Beta | 已检查键盘、焦点、label 和布局；没有正式第三方审计 |
| 安全 | 尽力维护 | 浏览器本地架构及自动依赖或代码检查能够降低风险；没有外部审计 |

## 已验证的不变量

仓库包含用于证明以下行为的测试：

- 二维码、Code 128 和 EAN-13 PNG 输出可由独立 `rxing` 测试依赖解码。
- Code 128 两侧各有 10 个模块的静区。
- EAN-13 左侧有 11 个模块的静区，右侧有 7 个模块的静区。
- EAN-13 会拒绝空白和非数字输入，不会悄悄规范化。
- Code 128 拒绝超过 128 字节的输入。
- Wi-Fi 凭据保留首尾空白并转义分隔符。
- 非有限值和超范围 Logo 比例会在图像解码前被拒绝。

这些测试通过不代表项目已认证所有打印尺寸、材料、相机、扫描器、光照或颜色组合。

## 兼容性基线

- 最低支持 Rust 版本：1.85
- Rust edition：2024
- Web 构建 target：`wasm32-unknown-unknown`
- Web runtime：支持 WebAssembly、JavaScript module、Blob 下载和标准 DOM API 的现代浏览器
- 主要托管环境：GitHub Pages
- 应用语言：英文和简体中文

仓库必须持续使用 Rust 1.85 编译。只在更新的 stable Rust 上运行 CI，不能替代 MSRV 检查。

## 已知限制

- 浏览器 UI 只接受最大 2 MiB 的 PNG Logo。
- Logo 生效时会有意禁用 SVG 下载，因为 Logo 合成只支持 PNG。
- Code 128 支持子集 B 或纯数字子集 C 情况，不支持子集 A 或混合子集切换。
- EAN-13 只接受前 12 位数字；用户不能提供已有的第 13 位校验位。
- vCard 输出字段较少，不执行电话或邮件校验。
- 电话和邮件模式只添加 URI 前缀，不验证目标语法。
- 应用没有离线 service worker、已保存项目、历史记录或批量流程。
- 项目没有 CLI、MCP 集成、Agent Skill、托管 API、npm release 或 crates.io release。
- 英文和简体中文是应用与项目文档中唯一作为一等版本维护的语言。

## 版本策略

项目使用 Semantic Versioning，但 1.0 之前的版本可能在 minor release 中修改契约。每个用户可见或 API 可见变更都必须记录在 changelog。Patch release 应在所属 minor line 内保持向后兼容，除非需要修复无法合理保留的不安全或错误行为。

达到 1.0 的条件包括：

1. 至少完成一个公开发布周期，并记录升级经验
2. 有意识地评审 Rust 和 WASM API
3. 发布产物可复现，并强制执行供应链检查
4. 有持续维护的多浏览器兼容矩阵
5. 公开错误语义和迁移策略稳定
6. 有持续真实使用和维护能力的证据
